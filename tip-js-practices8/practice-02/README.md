## 4. Модель данных и функции

Задача: `{ id, title, completed, priority }`. Правила: `id` — положительное безопасное целое, уникальное в списке; `title` — строка, после `trim()` 1–100 символов, сохраняется очищенной; `completed` — boolean (при создании `false`); `priority` — строго `low`/`medium`/`high`, по умолчанию `medium`.

| Файл | Назначение |
|---|---|
| `src/data.js` | `demoTasks`, `variantNumber`, `variantTasks` |
| `src/task-service.js` | девять функций; внутренние `fail`, `isValidId`, `normalizeTitle`, `checkId` |
| `src/main.js` | общий сценарий, сценарий варианта, вывод |
| `checks.js`, `my-checks.js` | готовые и собственные проверки |

| Функция | Успех | Ошибка |
|---|---|---|
| `createTask` | `{ ok: true, task }` | `{ ok: false, error }` |
| `findTaskById` | найденный объект (не копия) | `undefined` |
| `getPendingTasks`, `getTaskTitles` | новый массив | — |
| `getTaskStats` | `{ total, completed, pending, progress }` | — |
| `addTask`, `setTaskCompleted`, `renameTask`, `removeTask` | `{ ok: true, tasks }` (новый массив) | `{ ok: false, error }` |

**Почему id не равен индексу:** id — устойчивый идентификатор записи, он не меняется при удалении и перестановке; индекс — позиция в массиве, которая смещается. Поэтому поиск идёт по `task.id`, а не по `tasks[id]` (в `demoTasks` задача с id = 4 стоит на индексе 1).  
**Почему getTaskStats возвращает число, а не строку с процентом:** число пригодно для дальнейших вычислений и сравнений; округление и знак `%` — задача отображения (`progress.toFixed(1)` в `main.js`), иначе терялась бы точность.  
**Какие объекты копируются при изменении задачи:** новый массив (`map`/`filter`/spread) и новый объект только для изменяемой задачи (`{ ...task, completed }`). Остальные объекты переиспользуются — это допустимо, так как они не изменяются.

## 9. Вывод

В ПР1 вычисления выполнялись в одном скрипте на отдельных переменных; в ПР2 логика вынесена в функции, возвращающие значения (`{ ok, ... }`), данные — в объекты и массивы, код — в ES-модули.
